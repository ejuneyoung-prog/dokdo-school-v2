# 독도스쿨 아동 개인정보 보호와 회원가입 재개 설계 초안

작성일 2026-10-19 한국 시간. 운영 배포 전 검토본입니다. 현재 구현한 임시 입구 차단과 앞으로 구현해야 할 동의 절차를 구분합니다. 법적 근거는 현행 조문을 참고했으며, 실제 처리자·위탁·국외이전·보유기간을 확정하기 전에는 신규 가입을 다시 켜지 않습니다.

## 이번 검토본에서 바뀌는 내용

- `registrationEnabled:false`를 추가합니다. 설정이 없거나 문자열 true인 경우에도 신규 등록은 닫힙니다.
- 처음 가입하기 버튼은 HTML 초기 상태부터 숨기고, 화면 제어와 가입 함수에서도 막습니다. 카카오 시작은 등록 보류 설정과 기존 카카오 설정을 모두 확인합니다.
- 기존 이메일 로그인, 이미 저장된 세션 확인, 비밀번호 찾기와 복구, 현재 기기에서 로그아웃은 유지합니다. 계정 삭제·로그아웃 강제 실행·기록 초기화는 하지 않습니다.
- 한국어와 영어로 신규 가입·카카오 진입이 보류 중임을 안내합니다. 기존 기기 학습·놀이와 기록 보관은 유지합니다.
- 서버의 Supabase 가입 허용 설정, Kakao 공급자, 운영 시트와 공개 순위는 이번 수정에서 변경하지 않습니다. 따라서 화면과 사이트 제어기의 입구 차단이며 외부에서 직접 호출하는 가입 API 전체를 차단하는 조치는 아닙니다. 공개 전 서버 가입 차단도 별도 검토해야 합니다.

## 가입 이외에 남아 있는 수집 경로

현재 메인에는 선택 프로필의 닉네임·국가·학교명과 학교 구분이 남습니다. app.js의 프로필 저장 이후 자동 저장 및 답안 활동이 기존 Apps Script 기록지로 전송될 수 있습니다. GA4 이벤트와는 다른 경로입니다. 가입 버튼을 숨겨도 이 경로는 사라지지 않습니다.

이 경로는 순위·공개 범위에 영향을 주므로 이번 입구 숨김에서 임의로 바꾸지 않습니다. 재개 전에는 새 프로필 수집과 개인값 전송을 보류하거나, 아래 동의 확인을 서버에서 통과한 기록만 받도록 바꿔야 합니다. 기존 시트·계정·로컬 기록은 삭제하지 않고 현황과 적법한 처리 근거를 별도로 검토합니다. 학교명 기존 자료의 유지·비공개·삭제는 운영자가 결정할 사항입니다.

## 만 14세 확인 흐름

1. 이메일·카카오 인증·닉네임·학교 입력보다 먼저 만 14세 이상과 만 14세 미만 중 선택하게 합니다. 설명문에서 학년이나 수업용 나이대가 가입 동의용 연령 확인과 다름을 알립니다.
2. 생년월일 전체를 기본 수집하지 않습니다. 14세 구분값과 필요한 확인 상태만 사용합니다. 단순 자기신고는 확실한 연령 인증과 같지 않으므로 위험도에 맞는 합리적인 확인·허위 선택 방지 방식을 운영자가 정합니다.
3. 만 14세 이상은 처리방침과 필수 처리 목적을 확인한 뒤 가입합니다. 선택 수집·공개 순위·분석은 각각 별도로 선택하고 미리 체크하지 않습니다.
4. 만 14세 미만은 보호자와 함께 시작하기로 전환합니다. 동의가 끝나기 전에는 아동 계정이나 이메일·학교·공개 프로필·클라우드 기록을 만들지 않습니다. 계정 없이 현재 기기에서 이용할 수 있다는 선택을 제공합니다.
5. 아동이 보호자에게 연결을 요청할 때는 법정대리인 동의 확인에 필요한 성명·연락처 범위로 제한합니다. 주민등록번호·신분증·가족관계 서류는 기본 입력으로 받지 않습니다.
6. 처음 만 14세 미만을 선택한 뒤 새로고침·뒤로가기·카카오 직접 콜백으로 바꿔도 동의 대기를 우회하지 못하도록 서버 상태와 짧은 만료 토큰을 사용합니다. 로컬의 나이 선택값만 신뢰하지 않습니다.

법정대리인의 동의와 그 확인, 필요한 최소 정보의 예외, 아동이 이해하기 쉬운 고지는 [개인정보 보호법 제22조의2](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1020398523)를 기준으로 설계합니다. 이 문서의 구체적인 화면·저장 구조는 서비스 설계 제안입니다.

## 보호자 동의 방식

권장안은 보호자가 직접 관리하는 계정 아래 아동의 별칭 프로필을 만드는 방식입니다. 아동의 개인 이메일과 학교를 가입 필수값으로 만들지 않습니다. 보호자 자신의 서비스 이용 동의와 아동 정보 처리에 대한 법정대리인 동의를 구분합니다.

기본 절차는 다음과 같습니다.

1. 보호자에게 목적·항목·보유기간·선택권·철회 방법을 쉬운 문장으로 보여 줍니다.
2. 법정대리인임을 확인하고 동의 의사를 명시적으로 받습니다. 전화번호를 가지고 있다는 사실만으로 법정대리인 관계가 입증된다고 간주하지 않습니다.
3. 본인확인 제공자를 통한 휴대전화 확인과 동의 화면, 완료 통지를 연결하는 방식을 우선 검토합니다. 동의 확인 방법은 [개인정보 보호법 시행령 제17조의2](https://law.go.kr/LSW/lsInfoP.do?ancYnChk=0&lsId=011468)의 허용 방식과 실제 제공자 계약에 맞춰 정합니다.
4. 대안으로 동의 내용이 담긴 이메일을 보내고 법정대리인의 명시적 동의 회신을 받는 방식이 있습니다. 단순 이메일 소유 확인 링크만 누른 것을 보호자 동의 완료로 처리하지 않습니다. 이메일만 사용할 경우 대리인 관계 확인·재사용 방지·회신 증거와 수동 확인 절차를 함께 정해야 합니다.
5. 서버에서 검증이 끝난 뒤에만 아동 프로필을 생성하고 필요한 정보 처리·저장을 허용합니다. 프런트의 버튼 숨김이나 체크박스만으로 완료 상태를 만들지 않습니다.

동의 기록에는 신청 식별자, 보호자 확인 참조값, 동의한 목적·항목·처리방침 버전, 표시 언어, 동의·확인 시각, 철회 상태를 보관합니다. 본인확인 원문이나 주민번호·카드번호는 서비스가 보관하지 않는 구조로 계약합니다. 법정대리인 연락처와 동의 증거는 권한을 나눠 보호하고 조회 이력을 남깁니다.

개인정보 처리 필수 동의와 학교명·공개 순위·분석 같은 선택사항은 묶지 않습니다. 선택하지 않아도 기본 학습·게임은 이용할 수 있게 합니다. 법정대리인 동의가 거절·만료·철회되면 새 수집을 멈추고 계정·백업의 보관과 파기 절차를 적용합니다.

## GA4 개인 식별 정보 확인

현재 직접 구현한 이벤트 경로는 고정 이벤트 이름과 숫자·열거형 값만 허용합니다. 이메일·닉네임·학교·국가 선택값·계정 UID·보호자 정보·생년월일은 포함하지 않습니다. 페이지 URL의 쿼리·해시와 유입 경로의 상세 경로를 제거하고, 페이지 제목은 고정값으로 보냅니다. 계정 화면에는 GA 태그가 없습니다.

코드 검사와 개인정보 canary를 넣은 모의 실행에서는 금지값 유출을 발견하지 못했습니다. 다만 운영 GA4의 향상된 측정·폼/외부 링크/사이트 검색 자동 이벤트·맞춤 정의·이메일 및 쿼리 데이터 삭제 설정은 아직 관리자 화면에서 확인하지 않았습니다. 직접 이벤트 검사가 자동 수집 전체의 무전송 확인을 대신하지 않습니다. 개인이 입력한 검색어·링크 주소·폼 목적지에 개인값이 실리지 않는지도 별도로 확인해야 합니다.

[Google의 PII 금지 지침](https://support.google.com/analytics/answer/6366371/)에 맞춰 이메일을 해시한 값도 임의 전송하지 않고, 계정 user_id/user_properties와 연락처 기반 사용자 제공 데이터 기능을 사용하지 않는 설계를 권장합니다. 재개 전에 관리자 설정과 실제 전송 요청을 테스트용 canary로 확인합니다. [측정 정책](https://developers.google.com/analytics/devguides/collection/protocol/ga4/policy)도 함께 확인합니다.

Google 정책상 PII를 직접 보내지 않는 것과 개인정보보호법상 개인정보가 전혀 처리되지 않는 것은 다릅니다. GA의 쿠키·client_id·접속 IP 처리·접속 국가 추정은 별개로 고지·근거를 검토해야 합니다. 국가 선택값을 보내지 않아도 GA가 접속 지역을 추정할 수 있습니다.

제안 기본값은 연령·동의 상태가 불명확하거나 만 14세 미만인 경로에서는 GA를 로드하지 않는 방식입니다. 14세 이상 경로도 선택 분석에 동의하기 전에는 태그를 로드하지 않는 기본 동의 방식으로 검토합니다. 이 제안은 아직 구현하지 않았고, 현재 GA 설정이나 운영 측정은 이번 입구 숨김에서 바꾸지 않습니다.

## 다시 켜기 전 완료 기준

- 실제 개인정보처리자 명칭·연락처·책임자, 위탁자와 국외이전 현황, 실제 보유기간 확정.
- 동봉한 처리방침 초안을 실제 운영 내용으로 확정하고 한국어·영어 및 아동용 쉬운 안내 제공.
- 이메일·카카오 가입 전 연령 확인과 서버 기반 법정대리인 동의 확인 구현.
- Supabase 신규 가입·OAuth 신규 사용자 생성·직접 API 우회까지 서버에서 제한. 기존 계정 로그인과 신규 생성은 구분.
- 프로필·학교명·활동 자동 저장·Apps Script 입력에도 동의 권한 확인 적용. 기존 공개 기록의 적법 근거·범위 검토.
- 동의 거절·만료·재사용·철회·계정 전환·다중탭·위조 콜백·재방문·복구를 가상 계정으로 시험.
- 선택 분석·개인정보 무전송의 실제 관리자 설정과 네트워크 확인. 아동·연령 미확인 경로 기본 보호.
- 아직 실패한 17a227c 병합 WebKit 검사 원인 확인과 출시 대상 커밋의 검사 완료.
- 별도 PR32를 최신 기준으로 재검수. 카카오 실제 입장·첫 닉네임 저장·기기간 복원 실기 완료.
- 운영자에게 최종 변경·미해결 사항을 먼저 보고한 뒤 공개 활성화 결정. 플래그 하나만 켜는 것으로 동의 절차를 대체하지 않음.

이 설계는 대한민국 이용자를 기준으로 작성한 초안입니다. 해외 아동을 대상으로 적극 서비스할 범위를 정하면 해당 지역의 연령·동의 요건도 별도로 확인합니다.
