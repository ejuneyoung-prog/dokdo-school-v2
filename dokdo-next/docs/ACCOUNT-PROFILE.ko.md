# 로그인 상태와 첫 닉네임 설정

로그인한 뒤에도 메인과 놀이터가 고정 ‘로그인’을 표시하던 문제를 수정한다. 서버에서 계정을 확인한 뒤 ‘닉네임 · 내 기록’을 표시하고, 계정 메뉴에 내 기록·프로필 설정·로그아웃을 둔다. 프로필이 아직 없으면 ‘닉네임 설정’을 표시한다. 확인 중에는 계정 확인 중으로 표시하고, 확인 실패나 로그아웃 뒤에는 로그인을 표시한다.

## UX 근거
- Google 공식 Gmail 도움말: 오른쪽 위 프로필 사진에서 로그아웃. https://support.google.com/mail/answer/8154?hl=ko
- GitHub 공식 도움말: 오른쪽 위 프로필 사진에서 계정 메뉴 및 계정 전환. https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/switching-between-accounts
- 적용 판단: 닉네임으로 현재 계정을 식별하고 로그아웃은 계정 메뉴 안에 둔다. 로그아웃을 메인 행동으로 크게 강조하지 않는다.

## 첫 입장
로그인 후 서버 프로필이 없는 경우 닉네임 설정을 먼저 연다. 닉네임은 1~40자 필수, 국가(2글자 코드)와 학교·소속(최대 60자)은 선택이다. 이메일 로그인, 즉시 세션이 생긴 가입, 카카오 복귀, 계정 화면의 돌아가기 모두 같은 완료 조건을 쓴다. 비밀번호 재설정 중에는 팝업을 덮지 않는다. 취소하면 계정 화면에 머문다. 한국어·미국 영어를 팝업 안에서 바꿀 수 있다.

동일 계정 토큰 갱신이나 중복 SIGNED_IN 재검증은 입력창과 이동 요청을 보존한다. 다른 계정, 실제 로그아웃은 해당 요청을 폐기한다. 뒤로 가기 캐시 복원은 인증 컨트롤러를 새로 만들고 다시 서버 확인한다. 이전 SDK 로드·인증 요청의 응답은 세대 검사로 폐기한다.

## 저장 경계
프로필은 Supabase auth.users.user_metadata의 dokdo_school_profile_v1 아래 version/nickname/country/school만 저장한다. 사용자가 편집할 수 있는 표시 정보이며 권한 판단에 쓰지 않는다. 서버 getUser로 확인한 UID가 권한 기준이다. 고정 Bearer 토큰으로 /auth/v1/user를 PUT하고 응답 UID·내용, 서버 재조회, 현재 세션 UID를 확인한다. A 저장 중 B로 바뀌면 A의 완료 화면이나 이동이 B에 적용되지 않는다. 같은 프로필의 동시 수정은 마지막 쓰기 우선이다.

프로필 설정은 기존 학습/게임 로컬 키, 공개 순위 이름, Apps Script 기록을 읽거나 쓰지 않는다. 이전 기기 기록을 새 로그인 계정에 자동 귀속하지 않는다. 기기 기록의 계정 저장과 복원은 기존 명시적 버튼·본인 기록 확인 절차를 따른다. 표시용 프로필 캐시는 인증/설정 완료의 근거가 아니다.

메인·놀이터는 SDK 세션이 없는 익명 방문 및 격리 미리보기에서 SDK를 로드하거나 인증 요청을 보내지 않는다. 필요할 때 고정된 로컬 SDK만 읽는다. CSP 연결 허용은 두 운영 화면에 정확한 Supabase 프로젝트 한 곳만 추가한다. 계정 화면에 GA를 추가하지 않는다.

## 검증과 되돌림
회귀 376개 및 정적 검사 131개 통과. 실제 고정 SDK의 queued SIGNED_IN → 같은 UID 재검증 → 닉네임 저장 후 이동도 외부 통신 없는 통합 검사로 확인. 독립 redteam_integration은 메뉴 15개와 프로필·인증·언어 관련 113개를 직접 재실행하고 차단 결함 없음으로 보고했다. 실제 로그인된 QA에서 첫 팝업과 한영 전환 확인, 교수님 본인 닉네임 저장 실기는 입력 대기 중이다. 실기 완료 여부는 출시 기록에 별도로 남긴다.

반영 전 태그 before-account-profile-20261019 (0fb3c47). 되돌림은 해당 PR의 머지 커밋을 되돌리는 PR로 동일 검사를 수행한다. 운영 자료 삭제나 DB 되돌림은 필요 없다. 일시 중지는 account-config.js의 profileEnabled를 false로 하되 로그인 세션 키 전환 영향을 검토한다. 카카오 또는 개인 기록 플래그가 true인 동안 v2 PKCE 세션 키는 유지된다. 비밀 키·비밀번호는 코드와 이관팩에 넣지 않는다.
