# 문제 이의제기 — 서버 직접 접수 (2026-10-30)

## 무엇이 바뀌었나

- 예전: 단추를 누르면 `mailto:`로 메일 앱만 열렸습니다. 휴대폰·카톡 같은 앱 안 브라우저·학교 PC에서는 실제 발송이 거의 되지 않았고, V3 공개 뒤 접수 0건이었습니다.
- V3에서는 단추가 접힌 '조금 더 알아보기' 안에 있어 잘 보이지 않았습니다. 이제 해설 바로 아래에 보입니다.
- 이제: 앱이 기록 서버(Apps Script)로 `{t:'dispute'}`를 직접 보냅니다. 서버는 '이의제기' 시트에 한 줄을 남기고 officialdokdokorea@gmail.com 으로 알림 메일을 보냅니다.
- 서버가 '접수됨'으로 답한 경우만 접수 완료로 안내합니다. 서버가 예전 버전이거나, 신고가 몰려 거절되었거나, 답을 확인하지 못하면 창을 닫지 않고 그 이유와 [메일로 보내기] 단추를 보여 줍니다. 메일 앱은 학생이 단추를 눌렀을 때만 엽니다(나중에 저절로 열면 브라우저가 막을 수 있음).

## 보내는 값

문항 ID, 문제, 정답 보기, 의견(1,000자까지), 화면 언어, 나이대, 접수번호. 별명·학교 등 개인 정보는 보내지 않습니다. 의견 칸에도 이름·연락처를 적지 말라고 안내합니다.

## 몰림 막기

- 앱: 같은 기기에서 1분에 한 번
- 서버: 10분 단위 칸마다 전체 40건, 같은 문항 5건. 같은 접수번호는 한 번만 기록. 문항번호는 순위 규칙과 같은 형식만 받음
- 알림 메일은 하루 50통까지(넘어도 시트에는 남음)

## GA 이벤트

`dispute_open`, `dispute_sent`, `dispute_failed` — 문항 번호(qid)만 보냅니다.

## 서버 코드

운영 Apps Script 전체 파일은 공개 저장소에 넣지 않고 교수님께 따로 전달합니다. `docs/apps-script/Code.gs`는 2026-09-13 사본이며 운영본과 다릅니다(10/11 보강, 10/12 주간 순위 규칙이 빠져 있음). 운영 코드를 바꿀 때는 이 사본을 쓰지 말고 편집기의 현재 코드를 기준으로 합니다.
