독립 교육·보안 감사, 실제 휴대폰 검증, 기존 클라우드 이관까지 완료한 무결점 인증은 아닙니다.

## 먼저 열어 볼 곳
- `/dokdo-next/`: 실제 학습 화면. 빈 새 기록 또는 같은 브라우저의 기존 기록으로 시작합니다.
- `/dokdo-next/demo.html`: 가상 헤비유저 시연. 실제 기록과 분리합니다.

- 별도로 제공된 `dokdo-korea-school-v1.3-preview.html`: 서버 없이 여는 미리보기. 실제 기록을 읽지 않으며 새로고침하면 초기화됩니다.

## 이번에 실제로 합친 것
1. 독도 위치·한국 시간 기준의 낮/노을/밤 전환과 시간대별 미리보기.
2. 동도 500 + 서도 500 + 주변 기념 지점 25 = 1,025칸의 성장 경로.
3. 태극기, 노랑 → 흰색 → 에메랄드색의 반복 성장. 이전 바퀴의 길을 지우지 않습니다.
4. 작고 많은 불빛 대신 화면 크기를 고려한 경로와 태극기. 작은 화면은 깃발 일부를 묶어 보여주며 확대할 수 있습니다.
5. 기존 그림의 동도 시설 부분을 수정 사본으로 합성했습니다. 화면과 저장 이미지가 같은 그림을 사용합니다.
6. 강치 최대 10마리·새 호출 1분·관람하지 않을 때 일시 정지, 기존 초과 잔여시간과 보상은 보존합니다.
7. 240개 한·영 문항 유지, 역사 단원의 독도 연결 배경 보강, 배치고사는 섬 비교부터 시작.
8. 제목·주요 버튼은 Gmarket Sans, 문제·보기·본문은 S-Core Dream. 웹폰트가 실패해도 조작 가능하며 상태를 알립니다.
9. 날씨 모델자료 연결·캐시·오류/만료 처리. 기본 배포는 이용조건 확인 전 외부 호출을 하지 않습니다.

## 날씨를 켜기 전 — 필요한 설정 한 곳
`assets/site-config.js`의 `weather.nonCommercialConfirmed`는 기본 `false`입니다.
서비스 운영자가 Open-Meteo의 무료 비상업용 이용조건과 호출량 제한을 확인한 경우에만 `true`로 변경합니다.
광고·유료 서비스 등 상업적 사용에는 별도의 이용권한과 서버 측 프록시 설계가 필요합니다. 유료 API 키를 공개 JavaScript에 넣지 마세요.
이 설정을 하지 않아도 독도 시간·일출·일몰 계산과 모든 학습 기능은 작동합니다.
날씨 데이터가 없으면 '맑음'을 만들어 내지 않고 연결 상태를 표시합니다.
출처: https://open-meteo.com/en/pricing / https://open-meteo.com/en/terms

현재 구현의 날씨는 모델 기반 예보이며 독도 현장 관측이라고 표시하지 않습니다.
요청에는 독도의 고정 좌표만 들어가고, 이름·문항·점수·이용자 위치는 보내지 않습니다.
자료시각이 3시간을 넘으면 현재 날씨로 사용하지 않습니다. 외부 날씨 연결의 실제 성공 여부는 배포 환경에서 확인해야 합니다.

## 저장·보상의 정확한 의미
저장 키는 `dokdo-korea-school-cinematic-v1`을 유지합니다. 기존 문항 ID를 재사용하거나 삭제하지 않습니다.
기존 성취는 원본 기록을 보존하면서 최초 한 번 경로 시작값으로 옮깁니다.
이 시작값은 원래 기록의 누적 정답 또는 획득 불빛을 근거로 하며, 새 인정 규칙으로 재검증한 정답 수는 아닙니다.
화면에서 '이전 성취 포함'으로 구분합니다. 이전 호출권을 새 규칙으로 깎거나 재지급하지 않습니다.

새 보상은 같은 개념의 당일 중복을 제외한 인정 정답으로 쌓이고, 10회마다 새 호출권 하나를 얻습니다.
배치고사·오답 뒤 즉시 정정은 경로 보상에 중복 반영하지 않습니다.
학습 기록·불빛·봉화·경로는 주간 집계 변경으로 초기화하지 않습니다.
1,025칸은 게임의 학습 기념 단위입니다. 25는 실제 독도의 섬 개수가 아니며, 경로는 실제 등고선/등반로가 아닙니다.

현재 활성 코스는 240문항·60개념입니다. 하루 500개의 서로 다른 새 개념을 제공한다는 뜻이 아닙니다.
원래 1,513문항과 예전 48문항은 비활성 보관 자료입니다.

## 업로드 순서
1. 현재 사용 중인 앱에서 학습 기록 JSON을 비공개로 백업합니다.
2. 새 브랜치에서 이 패키지의 `dokdo-next/`를 기존 같은 폴더에 전체 갱신합니다.
3. `.github/workflows/dokdo-next-verify.yml`도 함께 갱신합니다.
4. 기존 루트의 `index.html`, Apps Script, 옛 questions.json은 지우거나 교체하지 않습니다.
5. GitHub Actions 검사 결과를 확인하고 미리보기 배포의 `/dokdo-next/`를 엽니다.
6. 새 사용자, 기존 기록 복사, 폰에서 JSON 내보내기/복원, 소리 켜기/끄기, 1분 관람을 직접 확인한 뒤 공개합니다.

파일 수가 많으므로 GitHub Desktop 또는 git 작업 디렉터리에 폴더째 복사하는 방식이 편합니다.
ZIP 자체를 저장소에 올리는 것은 사이트 배포가 아닙니다.
기존 루트 사이트가 곧바로 이 버전으로 바뀌는 패키지가 아닙니다.
코드 원복과 기록 원복은 다릅니다. 업데이트 이후 기록을 오래된 백업으로 덮어쓰지 마세요.

## 재검사
```sh
python -m pip install -r requirements-test.txt
python tools/content/build_course.py --check
python -m unittest tests.test_content_gate -v
npm test
node tests/migration.cjs test-results/migration.json
python tools/check_site.py test-results/static.json
python -m playwright install chromium webkit
python tests/release-13-browser.py --mode http --engine chromium --output test-results/native-chromium
python tests/clear-browser.py --mode http --engine chromium --phase matrix --output test-results/matrix-chromium
```
`--mode inline`은 통제된 저장소를 사용하는 검사입니다. 실제 주소의 저장 유지 검사를 대신하지 않습니다.
HTTP 주소 접근이 가능한 환경에서 기본 `--mode http`로 실행해야 합니다.
