# DOKDO TOGETHER 1차 시제품 인계 (부사장 · 재민이 · 미래전략실장용)

작성: 2026-11-20 · 브랜치 `feat/together` · 주소(병합 뒤) `https://dokdo-school-v2.vercel.app/dokdo-next/together/`

## 한 줄 요약

독도 앞바다에 태극기를 단 내 배를 띄워 매일 태극기를 올리고, 통발로 번 돈과 스쿨 학년으로 배(집)를 키우는 곳입니다. 1차는 이 기기 저장만 쓰고, 다른 배는 견본입니다.

## 2. 파일 지도 (`dokdo-next/together/`)

- `index.html` · `together.css`: 화면 틀
- `config.js`: 설정값 전부. 통발 시간, 돈 이름, 생물 표, 배 단계와 혜택, 꾸미기, 견본 수
- `rules.js`: 계산만 함(게양, 흔들기, 통발, 확률, 팔기, 배 키우기, 꾸미기, 계급)
- `user.js`: 이용자 상태(만들기, 고쳐 읽기)
- `fleet.js`: 바다 상태(배 자리 고리, 가까운 배 고르기, 태극기 순위)
- `store.js`: 저장소 인터페이스. 1차는 LocalStore + 견본 배
- `net.js`: 실시간 통신 자리(빈 구현)
- `bridge.js`: 스쿨에 기대는 모든 것(학년 읽기, 명예의 전당 읽기, 닉네임 받기, 스쿨·캠핑 문, 진동). 떼어 낼 때 이것만 바꿈
- `flag.js`: 태극기 그리기(비율 시험 있음)
- `ship.js`: 배·선실 모양(단계별 함수). 모양을 바꾸거나 단계를 늘릴 때 여기만
- `sea.js`: 3D 장면(힐링캠프와 같은 three.js 0.160, 같은 하늘·바다·지형)
- `share.js`: 9:16 공유 사진
- `terrain.js`: 생성물. `python3 tools/together/extract_terrain.py`로 힐링캠프에서 그대로 뽑음
- 시험: `tests/together.test.cjs`

## 3. 지킨 것

- 기존 힐링캠프(`camp/`)는 한 줄도 고치지 않았습니다. 지형만 읽어서 뽑았습니다.
- 대황, 공통포인트(P), 레벨 경험치와 섞지 않았습니다(#49 판정: 서버 원장 전에는 P 적립 금지).
- 스쿨 기록은 학년만 읽고 쓰지 않습니다. 닉네임은 스쿨 문이 어린이 보호 확인을 통과했을 때만 주소로 받습니다.
- 닉네임과 기록은 이 기기에만 저장되고, 밖으로 나가는 것은 명예의 전당 GET 하나뿐입니다.
- 스쿨 문은 닉네임을 주소 뒤 조각(`#nick=`)으로 넘깁니다. 이 조각은 서버로 가지 않아 접속 기록에 남지 않습니다.
- 공유 사진과 캠핑장 주소에 닉네임을 넣는 것은 스쿨과 같은 어린이 보호 확인(`DokdoPrivacy.mayShare`)을 통과한 기기뿐입니다.
- 그룹 브랜드 규정 V2를 따릅니다: 차콜 #232528 바탕, 판 #2E3135, 보조 글자 #A7ABB0, 라임 강조, 한글 G마켓 산스, 영문·숫자 발로 컨덴스드, 14px 이상, 남색·주황 장식 없음. 노랑 #FFD23F은 "시제품·견본" 알림에만 씁니다.
- 결제, 채팅, 자유 입력(닉네임 제외)은 없습니다. Apps Script와 구글 시트는 건드리지 않았습니다.

## 4. 견본 데이터

- 다른 배 48척은 `store.js`의 견본입니다. 이름은 "견본 선장 N"이고 실제 이용자가 아닙니다.
- 화면 위에 "시제품 · 다른 배는 48척이 견본입니다"를 늘 띄웁니다.
- 실제 저장소를 붙이면 견본을 빼고 이 표시도 지웁니다.

## 5. 2차 계획 (붙이는 순서)

1. 실제 저장소: Supabase(스쿨 계정과 같은 곳)에 `ships` 표 하나를 둡니다(id, 계정, 닉네임, 나라, 단계, 꾸미기, 지킨 날, 흔든 수, 갱신 시각).
   - 게양과 흔들기는 서버가 날짜(한국 시각)와 하루 상한을 셉니다. 지금은 기기 시계를 돌리면 하루를 건너뛸 수 있습니다.
   - "태극기 순위"를 공개 순위로 올리려면 서버 셈이 꼭 필요합니다(교수님 결정 사항: 순위 규칙, 공개 범위).
2. 닉네임 악용 방지: 금칙어 거르기(스쿨과 같은 목록), 신고와 숨기기, 어린이는 닉네임 대신 "선장 N" 표시를 선택할 수 있게 합니다. 명예의 전당 선단은 지금처럼 운영자 승인분만 씁니다.
3. 실시간 만남: Supabase Realtime 방 하나에 위치·깃발 흔들기만 주고받습니다(채팅 없음).
4. 예상 서버 비용 (Supabase 공개 요금표, 2026-11-20 확인)
   - Free: 월 $0. 월간 활성 50,000명, DB 500MB, Realtime 동시 접속 200, 메시지 월 200만 건
   - Pro: 월 $25부터. 월간 활성 100,000명, DB 8GB, 동시 접속 500, 메시지 월 500만 건
   - Pro 초과분: MAU당 $0.00325, 동시 접속 1,000당 $10, 메시지 100만 건당 $2.50
   - 배 한 척은 수백 바이트라 10만 척도 DB 수십 MB 수준입니다(추정).
   - 실시간 동시 접속이 200명을 넘는 시점부터 Pro가 필요합니다. 스쿨이 이미 Supabase를 쓰고 있으면 같은 요금제를 나눠 씁니다(현재 요금제는 미확인).
5. 2차 기능 자리(만들지 않음, `config.js` LATER): 낚시 → 오늘의 문제 보상 → 응원 깃발 → 선장 복장·강치·삽살개 → 라이브 명예의 전당 → 실제 저장소·실시간

## 6. 검사 결과 (기기별)

- 노드 시험: `tests/together.test.cjs` 20개 통과. 전체 `npm test` 586개 통과, check_site 217개 통과.
- 브라우저 시험 `tests/together-browser.py`: GitHub 검사(CI)에는 아직 연결하지 못했습니다. 이 맥의 GitHub 권한에 워크플로 수정 권한(workflow)이 없어 CI 설정을 바꿀 수 없었습니다. 대신 이 맥미니에서 저장소와 같은 playwright 1.57.0으로 chromium과 webkit(아이폰 사파리와 같은 엔진) 두 엔진을 돌려 모두 통과했습니다(11/20). CI에 넣으려면 `.github/workflows/dokdo-next-verify.yml`의 native-browser 단계에 `- run: python tests/together-browser.py ${{ matrix.engine }}` 한 줄을 더하면 됩니다.
- 이 맥미니 헤드리스 크롬(소프트웨어 렌더링)
  - 휴대폰 폭 390px: 첫 화면, 게양, 통발, 건지기, 팔기, 배 키우기, 꾸미기, 순위, 사진(1080×1920)을 확인했습니다. 오류 0건.
  - 좁은 폭 320px과 가로 화면 844×390: 메뉴 여섯 칸이 모두 보이고, 목표 판이 내 배를 가리지 않습니다.
  - 참고 수치(소프트웨어 렌더링, 실제 기기 아님): 390px에서 첫 그림 약 0.4~2초, 초당 60장. 1280px에서는 초당 약 19장.
  - 컴퓨터 폭 1280px: 같은 흐름을 확인했고 오류 0건입니다.
- 인스타그램 앱 안 · 아이폰 사파리: 실제 기기에서 확인하지 못했습니다(미확인).
  - 헤드리스 크롬에 인스타그램 아이폰 사용자 문자열만 씌워서, "길게 눌러 저장" 안내로 넘어가는 것만 봤습니다. 엔진이 크롬이라 실제 사파리·인앱 확인을 대신하지 못합니다.
  - webkit(사파리 엔진)은 이 맥미니의 playwright로 확인했습니다. 실제 아이폰과 인스타그램 앱 안 브라우저는 여전히 미확인입니다.
- 첫 화면이 뜨는 시간과 끊김의 실제 기기 수치: 미확인. 헤드리스 수치는 HANDOFF 보고서 본문에만 참고로 적었습니다.

## 7. 되돌리는 법

`together/` 폴더 하나와 `tests/together.test.cjs`, `tools/together/`, `package.json`의 시험 한 줄만 더했습니다. PR 병합 커밋을 `git revert -m 1 <병합 커밋>` 하면 그대로 사라지고, 다른 화면에는 영향이 없습니다.

## 8. 레드팀 1차(11/20) 지적과 조치

- 치명: 학년을 저장 칸에서 읽어 모두 유치원으로 보였습니다 → 스쿨과 같은 계산(dokdo-core)으로 고쳤습니다.
- 높음: 명예의 전당 학년 글자를 못 읽었습니다 → '독코민 Lv.N'과 'Lv.N'을 되읽습니다.
- 높음: 사진·캠핑장 주소에 닉네임이 보호 확인 없이 들어갔습니다 → 보호 확인 뒤에만 넣습니다.
- 높음: 배를 바꿔 그릴 때 그래픽 메모리를 풀지 않았습니다 → 풀고, 카메라가 충분히 움직일 때만 다시 고릅니다.
- 중간(모두 고침): 자정 뒤 태극기 올리기가 막히던 일, 다른 탭 기록 덮어쓰기, 미래 시각 통발, 저장 안내 문구, 문어 확률(15%로 낮추고 출처 주소 추가), 머리 숫자에 견본 섞임, 열리지 않는 계급 목표, 화면 읽기 1초 반복, 좁은 화면·가로 화면 배치, 이름표 겹침
- 남은 것: 개인정보 안내 페이지(privacy.html)에 TOGETHER 내용이 아직 없습니다. 안내 문구는 교수님 확인 뒤 넣습니다.

## 9. 레드팀 2차(11/20) 지적과 조치

- 1차 수정은 모두 실제로 작동함을 확인받았습니다(학년 계산, 명예의 전당 글자, 어린이 보호 끝까지, 그래픽 메모리, 자정, 다른 탭, 공유, 문어, 머리 숫자, 목표, 화면 읽기, 좁은·가로 화면, 이름표).
- 높음
  - 두 PR(이 페이지와 스쿨 문)이 package.json 시험 줄에서 충돌했습니다 → 스쿨 문 PR을 이 PR 위에 쌓았습니다. 이 PR을 먼저 병합합니다.
  - 이 문서의 "CI에서 webkit 확인"은 사실이 아니었습니다 → 고쳤습니다(위 6절). webkit은 이 맥미니에서 직접 돌려 통과했습니다.
  - 처음 온 사람이 60분 동안 할 일이 없었습니다 → 첫 통발만 3분, 기다리는 동안 막대는 통발 진행, 학년이 막히면 남은 문제 수와 "스쿨에서 공부하기" 단추를 보여 줍니다.
- 중간(모두 고침): 학년 막힘 때 거짓 50% 막대, 사진 창 단추가 화면 밖, 사진 글자 14px 미만(42·40px로), 출처에 없는 새우 별명·"가장 큼"(뺌, 도화새우는 "대형종, 최대 25cm"), 사진에 견본 배(사진 찍을 때 숨김), 닉네임 길이 12·20 불일치와 NFC(둘 다 20자·NFC), 라임 부표(흰색으로), 스쿨 문의 어색한 영어 문구, 개인정보 안내에 TOGETHER 내용 추가
- 낮음(고침): 조사(을/를·로/으로), "곧 열립니다" 약속 문구, "첫째 고리/첫째 줄" 겹침(안쪽 고리 / 맨 앞 줄), 저장 막힘 안내가 가려지던 일, 두 번 빨리 누르기, 목록 밖 나라 코드, ?nick= 주소(이제 #nick=만 받음)
- 남은 것: 3D를 켤 수 없는 기기의 사진에는 배 그림이 없습니다(태극기와 글자만). 시계를 돌려 지킨 날을 늘리는 것은 서버가 붙기 전의 알려진 한계입니다.
