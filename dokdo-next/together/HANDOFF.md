# DOKDO TOGETHER 1차 시제품 인계 (부사장 · 재민이 · 미래전략실장용)

작성: 2026-11-20 · 브랜치 `feat/together` · 주소(병합 뒤) `https://dokdo-school-v2.vercel.app/dokdo-next/together/`

## 한 줄 요약

독도 앞바다에 태극기를 단 내 배를 띄워 매일 태극기를 올리고, 통발로 번 돈과 스쿨 학년으로 배(집)를 키우는 곳입니다. 1차는 이 기기 저장만 쓰고, 다른 배는 견본입니다.

## 1. 무엇을 만들었나

| 기능 | 상태 | 비고 |
|---|---|---|
| 첫 배(닉네임·나라 → 태극기 단 작은 배, 다시 와도 그대로) | 구현 | 이 기기 저장(`dokdo-together-v1`) |
| 매일 게양 · "독도를 지킨 날 N일째"(하루 빠져도 줄지 않음) | 구현 | 한국 시각 자정 기준 |
| 통발 던지기 → 건지기 → 바로 다시 던지기 | 구현 | 기다림 = `TRAP_MINUTES`(60분) × 계급 배율 |
| 통발 확률표(흔한 것 3 · 귀한 것 1) | 구현 | `config.js` CATCH 표 하나 |
| 팔기(게임 속 돈, 이름 미정) | 구현 | 돈 이름은 `config.js` MONEY |

| 계급 혜택(통발 수·기다림·정박 자리·큰 태극기) | 구현 | 계급이 높을수록 독도 가까이 정박 |

| 명예의 전당 선단(스쿨 퀴즈 최고 단계 도달자 → 첫째 줄 금빛 돛대) | 구현 | 운영 Apps Script 공개 응답 `?tops=1` 읽기만. 확인 시점(11/20) 승인된 명단 0명 |
| 태극기 흔들기 · 태극기 순위 | 일부 구현 | 하루 20번까지 셈. 순위는 이 기기 안(견본 포함)만. 모두의 순위는 서버 뒤 |
| 공유 사진(세로 9:16, 내 배·태극기·수호 일수) | 구현 | 공유 시트 → 내려받기 → 길게 눌러 저장 순서 |
| 태극기(작도법 비율) · 흔들림 | 구현 | 색 값은 근삿값[확인필요] |
| 스쿨로 가는 문 · 캠핑장(힐링캠프)으로 가는 문 | 구현 | 스쿨 첫 화면 쪽 문은 별도 PR |
| 몰입 설계(다음 목표 한 줄 · 즉각 반응 · 기다림 잇기) | 구현 | `app.js` 머리말 |
| 실시간 만남 · 실제 저장소 | 미구현(2차) | 자리만(`net.js`, `store.js`) |

## 2. 파일 지도 (`dokdo-next/together/`)

- `index.html` · `together.css`: 화면 틀
- `config.js`: 설정값 전부. 통발 시간, 돈 이름, 생물 표, 배 단계와 혜택, 꾸미기, 견본 수
- `rules.js`: 계산만 함(게양, 흔들기, 통발, 확률, 팔기, 배 키우기, 꾸미기, 계급)
- `user.js`: 이용자 상태(만들기, 고쳐 읽기)
- `fleet.js`: 바다 상태(배 자리 고리, 가까운 배 고르기, 태극기 순위)
- `store.js`: 저장소 인터페이스. 1차는 LocalStore + 견본 배
- `net.js`: 실시간 통신 자리(빈 구현)
- `bridge.js`: 스쿨에 기대는 모든 것(학년 읽기, 명예의 전당 읽기, 닉네임 받기, 스쿨·캠핑 문, 진동). 떼어 낼 때 이것만 바꿈
- `flag.js`: 태극기 그리기(비율 시험 있음)
- `ship.js`: 배·선실 모양(단계별 함수). 모양을 바꾸거나 단계를 늘릴 때 여기만
- `sea.js`: 3D 장면(힐링캠프와 같은 three.js 0.160, 같은 하늘·바다·지형)
- `share.js`: 9:16 공유 사진
- `terrain.js`: 생성물. `python3 tools/together/extract_terrain.py`로 힐링캠프에서 그대로 뽑음
- 시험: `tests/together.test.cjs`

## 3. 지킨 것

- 기존 힐링캠프(`camp/`)는 한 줄도 고치지 않았습니다. 지형만 읽어서 뽑았습니다.
- 대황, 공통포인트(P), 레벨 경험치와 섞지 않았습니다(#49 판정: 서버 원장 전에는 P 적립 금지).
- 스쿨 기록은 학년만 읽고 쓰지 않습니다. 닉네임은 스쿨 문이 어린이 보호 확인을 통과했을 때만 주소로 받습니다.
- 닉네임과 기록은 이 기기에만 저장되고, 밖으로 나가는 것은 명예의 전당 GET 하나뿐입니다.
- 결제, 채팅, 자유 입력(닉네임 제외)은 없습니다. Apps Script와 구글 시트는 건드리지 않았습니다.

## 4. 견본 데이터

- 다른 배 48척은 `store.js`의 견본입니다. 이름은 "견본 선장 N"이고 실제 이용자가 아닙니다.
- 화면 위에 "시제품 · 다른 배는 48척이 견본입니다"를 늘 띄웁니다.
- 실제 저장소를 붙이면 견본을 빼고 이 표시도 지웁니다.

## 5. 2차 계획 (붙이는 순서)

1. 실제 저장소: Supabase(스쿨 계정과 같은 곳)에 `ships` 표 하나를 둡니다(id, 계정, 닉네임, 나라, 단계, 꾸미기, 지킨 날, 흔든 수, 갱신 시각).
   - 게양과 흔들기는 서버가 날짜(한국 시각)와 하루 상한을 셉니다. 지금은 기기 시계를 돌리면 하루를 건너뛸 수 있습니다.
   - "태극기 순위"를 공개 순위로 올리려면 서버 셈이 꼭 필요합니다(교수님 결정 사항: 순위 규칙, 공개 범위).
2. 닉네임 악용 방지: 금칙어 거르기(스쿨과 같은 목록), 신고와 숨기기, 어린이는 닉네임 대신 "선장 N" 표시를 선택할 수 있게 합니다. 명예의 전당 선단은 지금처럼 운영자 승인분만 씁니다.
3. 실시간 만남: Supabase Realtime 방 하나에 위치·깃발 흔들기만 주고받습니다(채팅 없음).
4. 예상 서버 비용 (Supabase 공개 요금표, 2026-11-20 확인)
   - Free: 월 $0. 월간 활성 50,000명, DB 500MB, Realtime 동시 접속 200, 메시지 월 200만 건
   - Pro: 월 $25부터. 월간 활성 100,000명, DB 8GB, 동시 접속 500, 메시지 월 500만 건
   - Pro 초과분: MAU당 $0.00325, 동시 접속 1,000당 $10, 메시지 100만 건당 $2.50
   - 배 한 척은 수백 바이트라 10만 척도 DB 수십 MB 수준입니다(추정).
   - 실시간 동시 접속이 200명을 넘는 시점부터 Pro가 필요합니다. 스쿨이 이미 Supabase를 쓰고 있으면 같은 요금제를 나눠 씁니다(현재 요금제는 미확인).
5. 2차 기능 자리(만들지 않음, `config.js` LATER): 낚시 → 오늘의 문제 보상 → 응원 깃발 → 선장 복장·강치·삽살개 → 라이브 명예의 전당 → 실제 저장소·실시간
