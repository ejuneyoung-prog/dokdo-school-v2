# 독도 힐링캠프 2.0 · P01 개발 인계

## 실행

`dokdo-together-p01/index.html`을 Chrome에서 엽니다. 파일 4개(HTML, CSS, JS 2개)를 같은 폴더에 둡니다. 설치, 서버, 계정, 외부 라이브러리가 필요 없습니다.

작업 브랜치는 `dev/dokdo-together-p01`이며 기준은 `ejuneyoung-prog/dokdo-school-v2`의 `main` 커밋 `7131df433f0f6c370096dfb3aadb80f8e75d7aad`입니다.

## 코드 시작점

- `scene.js`의 `createPlaza`는 플레이어 상태와 렌더러를 제공합니다. XYZ 좌표를 원근 투영해 Canvas 2D에 그립니다. 섬은 상징적인 저폴리 지형입니다.
- `controls.js`에서 키보드·포인터 입력을 수집해 위치와 방향을 계산합니다. 위치 갱신과 깃발 동작을 분리해 두었습니다.
- 기존 `dokdo-next/camp/view.js`에는 2D 독멍, `heal-econ.js`에는 레벨·대황, `healing.js`에는 관광 및 `claude.use('room')` 기반 접속 코드가 있습니다. P01은 별도 경로에서 실행되고 해당 상태나 API를 사용하지 않습니다.
- 원래 ZIP은 작업 환경에서 확인할 수 없었습니다. 이전 시제품 설명에 등장한 닉네임, 카메라 전환, 인사, 사진 저장은 이번 구현 범위 밖입니다.

## Claude · 화면과 조작 검수

`TEST_REPORT.md` 순서대로 시작한 뒤 사파리와 휴대전화 실기기에서 길게 누르기, 멀티터치, 화면 회전, 포커스 이탈 뒤 이동이 멈추는지 확인합니다. 태극기 문양과 애니메이션을 검수합니다. 얼굴 깊이 기반 정렬을 사용해 캐릭터와 깃발이 겹칠 때 가림 순서가 어긋날 수 있습니다.

## 재민이 · 실시간 접속 설계 및 통합 검증

P01의 자동 캐릭터 5명은 접속자가 아닙니다. 실제 접속을 추가할 때 플레이어 상태를 위치·방향·깃발 상태로 전달할 수 있도록 인터페이스를 정하고, 접속 종료와 재접속 시 다른 기기의 상태가 정리되는지 개발 환경에서 확인합니다. 별도 기기 두 대의 입장·이동·흔들기·퇴장 시나리오를 통과 조건으로 둡니다. 운영 계정·보상 연동은 별도 검토 대상입니다.
